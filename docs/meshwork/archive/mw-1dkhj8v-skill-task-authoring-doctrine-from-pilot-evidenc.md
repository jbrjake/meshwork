Three behaviors the pilot's work session paid for that the distributed
skill should teach, since the binary cannot force them: (1) task titles
are IMPERATIVE ACTIONS, not findings — "leras's OWN walk is at parity
through the scan door (0.95x)" hid the required fix behind a
descriptive title until the user detonated; the recovery retitle was
"FIX THE DOOR"; (2) a verify must be RED while the work is undone
(pair with [[red-check]] once it exists — until then it is doctrine);
(3) mirror the in-flight meshwork task into the harness's console todo
surface for human visibility — the user's "YOU'RE GIVING ME NO
VISIBILITY" complaint was answered by duplicating store state into the
console list by hand; the skill should prescribe that from the start.
Also: handoffs are implementation briefs (name the code sites, forbid
re-derivation), not summaries.
